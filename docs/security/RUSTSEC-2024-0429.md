# RUSTSEC-2024-0429 — glib `VariantStrIter` unsoundness

**Status:** Accepted / ignored until Tauri 3  
**Advisory:** [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html) (GHSA-wrw7-89jp-8q8g)  
**Locked version:** `glib` 0.18.5  
**Fixed in:** `glib` ≥ 0.20.0

## Why we cannot bump

Dependabot cannot resolve this. Tauri 2’s Linux backend depends on archived GTK3 bindings (`gtk` 0.18 / `webkit2gtk` 2.0), which require `glib ^0.18`. The earliest fixed release is 0.20.0 and needs the GTK4 stack (expected with Tauri 3). Upstream declined a 0.18.6 backport.

## Exposure in this project

| Target | Impact |
|--------|--------|
| Windows | None — `glib` is not in the Windows dependency tree (WebView2). |
| Linux | Transitive via `webkit2gtk`. Bug is local UB / null deref if `VariantStrIter` runs in a release build — not a typical remote exploit. |

We do not call `VariantStrIter` directly. Ignore entry lives in `.cargo/audit.toml`.

## Revisit when

- Upgrading to Tauri 3 / GTK4, or
- A `glib` 0.18.x patch release appears on crates.io
